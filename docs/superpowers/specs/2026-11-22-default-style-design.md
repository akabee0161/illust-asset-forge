# 共通のデフォルトの画風（設計）

## 目的

依頼者の構想: まず画風を固定してデフォルトにし、その上でキャラクター固有の雰囲気・服・武器などを個別に指定する。今は全キャラクター共通のデフォルトが無く、`character.yaml` ごとに `style:` を必ず書く作りなので、画風を変えるにはキャラクターの数だけ書き換える必要がある。

画風は全員共通のデフォルトを 1 か所で決め、キャラクターの設定には固有の外見・服・持ち物だけを書けばよいようにする。1 人だけ別の画風にしたいときは、その人の `character.yaml` に書けば上書きできる（今のところ上書きの予定は無いが、依頼者の構想に最も合う）。

## 進め方の候補

- **A. 共通のデフォルトを 1 か所に置き、キャラクターごとの指定は必要なときだけ書く（採用）**
- B. キャラクターごとの指定をなくし、共通の画風だけにする: Colab で 1 人だけ別の画風を試して採用したとき、書き戻す場所が無い（書き戻すと全員のデフォルトが変わる）
- C. 仕組みは変えず、各 `character.yaml` の `style:` を書き換える: デフォルトの仕組みにならず、新しいキャラクターのたびに画風名を書く必要が残る

## 仕組み

- リポジトリ直下に `defaults.yaml` を置き、`style: thick-line-flat` と書く
- `character.yaml` の `style:` は省略できる。省略したら `defaults.yaml` の `style` を使い、書いてあればそれを使う
- 省略したのに `defaults.yaml` が無い、または `style` が無い・文字列でないときは `ConfigError` で止める（`<相対パス>: <キーの位置>: <何がおかしいか>` の形）
- 直すのは設定の読み込み（`src/artgen/config.py` の `load_character`）だけ。`Character.style` は、デフォルトを当てはめた後の画風名のままにするので、生成・取り込みの側は変えない

## 取り込みの決まり

Colab で別の画風を試して採用したときは、今と同じく、その画風をそのキャラクターの `character.yaml` に書き戻す（そのキャラクターだけの上書きになる）。デフォルトと同じ画風なら、書き戻しの一覧に出ない（`overrides.style` は、使った画風がそのキャラクターの画風と違うときだけ記録されるため）。

## キャラクターの設定

- セラ（ally06）: `style: soft-cel` の行を消し、デフォルトに従わせる
- ボルグ（ally05）: `style: color-anime` の行を消し、デフォルトに従わせる（依頼者が決めた）。採用・書き出し済みの顔・表情・全身は color-anime のまま残る。表情・全身は採用した顔の画風を引き継ぐので、顔を新しい画風で作り直すまでは color-anime で作られる

## ドキュメントとテスト

- README: ファイルの地図に `defaults.yaml` を足し、画風の決まり方（デフォルト → 個別の上書き → `style=` 引数での一時的な差し替え）を書く
- ノートブック: `STYLE = None` の説明を「デフォルト（キャラクターに個別の指定があればそれ）」に直す
- CLAUDE.md: 新しいキャラクターの `character.yaml` には `style:` を書かない。書き戻しで `style` を書くのは、デフォルトと違う画風を採用したときだけ
- テスト: 省略したらデフォルト、書いたらそれが優先、省略して `defaults.yaml` が無い・`style` が無いと止まる、リポジトリの `defaults.yaml` の画風が `styles/` にある

## やらないこと

- ノートブックの `style=` 引数での一時的な差し替えは今のまま残す
