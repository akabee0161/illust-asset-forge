# illust-asset-forge 設計書

作成日: 2026-11-21（このファイルは作成時点のログ。最新の状態は README.md と CLAUDE.md を正とする）

## 1. 目的と背景

ゲーム用のキャラクターのイラスト（顔・表情の差分・全身絵）を、Google Colab の GPU で生成する汎用のリポジトリを作る。

- 依頼者は今、Colab のノートブック 1 冊（似たセルが 4 つあり、少しずつ違う）で、Animagine XL 4.0 の顔のイラストを生成している。セルの違いはほぼ「プロンプト」「シードの決め方（ランダム・固定の一覧・1 つだけ）」「保存するファイル名」の 3 点で、モデルの読み込みと保存の処理は同じ
- 今回は**生成した画像を作業の流れに入れられるかを試す段階**。試した結果を見て、character-tactics の前提（顔の画像の規約・表示の大きさ）を変えるかを依頼者が決める
- 最初に使うのは character-tactics の ally05 ボルグ（盾役の男性前衛、近接、スキル「引きつける」）。ボルグのドット絵の作業は、顔と全身絵ができるまで止まっている
- リポジトリはゲームに依存させない。ゲーム側は、書き出した画像を受け取るだけ

## 2. 目標・目標外・失敗とみなすこと

### 目標

1. キャラクターの設定（YAML）・画風・絵の種類から、プロンプトを組み立てて生成できる
2. 顔（通常）を正方形で何枚か生成し、依頼者が 1 枚選べる
3. 採用した顔の目と口のあたりだけを inpaint で描き直し、表情の差分を作れる
4. 全身絵（参考資料）を生成できる
5. 採用した画像を、生成の条件ごと受け渡しの形に書き出せる
6. 採用した画像を、条件から作り直せるように記録する（ただし完全な再現は保証しない。8 章）

### 目標外（今回は作らない）

- 三面図（前・横・後ろ）。型を足せば作れる作りにしておくが、型は作らない
- IP-Adapter による顔の条件付け。全身絵の髪の色・髪型が顔と合わなかったときだけ足す
- LoRA の学習（構図を変えた絵が要るようになってから）
- 顔の自動検出・自動の切り出し
- Google Drive からこのサーバーへの自動の取り込み、Colab からの直接の push（後で切り替える。4.2）
- character-tactics の規約・画面・コードの変更。表情の差分をゲームで出す作業、顔の表示を大きくする作業、顔の PNG の差し替えは character-tactics 側の別の作業

### 失敗とみなすこと（動いても失敗）

- リポジトリが character-tactics の事情（ファイル名・`FACE_PX`・JSON の形）を知っている
- 1〜2 体を試す段階なのに、今のノートブックより手間が増える
- 生成の条件が残らず、採用した絵を作り直せない
- 範囲を広げすぎる（目標外のものを先回りして作る）

## 3. 前提と制約

- **GPU を使う処理は依頼者が Colab で実行する。** このサーバーには GPU が無いので、Claude は GPU を使う処理を動かして確かめられない。GPU なしで動く部分（設定の読み込みと検証・プロンプトの組み立て・PNG の条件の読み書き・書き出し）はテストで確かめる
- Colab の GPU は T4（VRAM 16GB）を想定する。SDXL を fp16 で 1 つだけ載せる
- モデル: `cagliostrolab/animagine-xl-4.0`、スケジューラは Euler a（`EulerAncestralDiscreteScheduler`）。今のノートブックの既定値（guidance 5、28 steps）を引き継ぐ
- シードは今と同じく CPU の `torch.Generator` で固定する
- **ライセンス**: Animagine XL 4.0 は CreativeML Open RAIL++-M（SDXL と同じ、制限の追加なし）。本文の「The Output You Generate」に、ライセンスを出した側は生成物に権利を主張しないとあり、商用利用も認められている。生成物の使い方の責任は使う側が負い、Attachment A の禁止用途には使えない。モデルを配らないので、ライセンスの写しを付ける決まりは関係しない。ゲームに使うことはライセンスの上で問題ないと判断した（Hugging Face のモデルのページと SDXL の LICENSE.md、2026-11-21 取得。法律の専門家の判断ではない）
- リポジトリは**公開**（GitHub、akabee0161）。Colab から鍵なしで clone できる
- **Colab は GitHub からリポジトリを取るので、Claude がこのサーバーで直した設定は、push するまで Colab に届かない。** push は依頼者が頼んだときだけ行う

## 4. 作り方

### 4.1 検討した作り方

| 作り方 | 内容 | 採否 |
|---|---|---|
| **A. .py のライブラリをノートブックから関数で呼ぶ** | 最初のセルでモデルを 1 回読み込み、以後のセルは `forge.generate("ally05", "face", n=8)` のような 1 行 | **採用** |
| B. コマンドとして呼ぶ | `!python -m artgen face ally05` | 不採用。実行のたびにモデルを読み込み直し、1 回ごとに 1〜2 分余計にかかる |
| C. ノートブックだけで作る | Colab の入力欄で条件を変える | 不採用。依頼者が「処理は .py に置く（差分が読める、テストが書ける）」と決めている |

A を採る理由: モデルをメモリに載せたまま、顔・inpaint・全身絵で使い回せる。inpaint のパイプラインは同じ重みを共有して作り（diffusers の `from_pipe` など）、T4 に 2 つ目のモデルを載せない。

### 4.2 受け渡しの流れ（依頼者が決めた: A 案＝チャットに添付）

```
[Claude] characters/<id>/character.yaml を書く → 依頼者が確認 → push（依頼者が頼む）
[依頼者・Colab] 生成 → 候補を Google Drive に保存 → Colab の画面で見比べる
[依頼者] 採用した PNG を手元にダウンロード → zip にしてチャットに添付
[Claude] characters/<id>/source/ に置く → PNG の条件を読む → 書き出し → コミット
```

- 候補はすべて Colab から Google Drive に保存する（セッションが切れても残る）。リポジトリには入れない（1 枚 1〜2MB あり、すぐ重くなる）
- リポジトリに入れるのは、採用した元の画像（`source/`）と、書き出した画像と `params.json` だけ
- 添付で PNG の条件が消えたり画像が縮められたりしないかは、最初の 1 回で Claude が確かめる。zip にすれば避けられる見込み
- 後で B（Drive 経由で Claude が取る）か C（Colab から push）に切り替える前提。切り替えやすいよう、取り込みと書き出しは「PNG のファイルを受け取る」ところから始める作りにする

### 4.3 顔を正方形にする（依頼者が決めた: ①最初から正方形で生成）

character-tactics は顔の画像を、縦横比を無視して正方形の枠に引き伸ばして描く（`src/render/sprites.ts` の `drawSquareOrCircle`）。縦長の画像を渡すと顔が潰れる。そのため:

- 顔の型は **1024×1024** で生成し、構図のタグで顔を大きく描かせる（今のロランの顔のように、頭と肩の上のほうが枠いっぱいに入る構図）
- 書き出しでは**縮めるだけ**（切り出さない）。大きさは **256×256**

256 の根拠: character-tactics の画面は 540×945 を基準に端末に合わせて拡大される。一般的なスマホで 64px の枠は実画面でおよそ 140 画素、32px の枠でおよそ 70 画素になる。1024 の画像をブラウザが一度に縮めると線が粗くなりやすく、人数分・表情分入れると読み込みも重くなる。表示を大きくすると依頼者が後で決めたときは、書き出しの大きさを設定で変えて作り直せばよい（元の 1024 は `source/` に残る）。

### 4.4 表情の差分（inpaint）

- 採用した顔（1024×1024）を入力にして、表情ごとに追加のタグを足し、決めた範囲だけを描き直す
- 描き直す範囲は、**採用した顔ごとに Claude が画像を見て決め**、目と口を囲む四角（1024 の座標）を `character.yaml` に書く。顔の自動検出は入れない
- 範囲の端は少しぼかして、描き直した部分と元の絵の境目を目立たなくする（ぼかしの幅は設定で変えられる）
- 1 つの表情につき何枚か候補を作り、依頼者が選ぶ（顔と同じ流れ）
- 入力の顔は、Drive にある採用した候補のパスか、リポジトリの `characters/<id>/source/face.png`（push 後）のどちらでも渡せる

### 4.5 全身絵（参考資料）

- 832×1216 で生成する（今のノートブックの大きさ）
- 背景は白か単色。服の種類・色・持ち物が分かることが目的で、顔立ちを厳密に合わせる必要はない（髪の色・髪型が合えばよい）
- 書き出しでは縮めない（ドット絵を描くときに細部を見るため）

## 5. 構成

```
illust-asset-forge/
  src/artgen/
    config.py      YAML の読み込みと検証（足りない項目・知らない表情名は、どのファイルのどこかを示して止める）
    prompt.py      画風 × キャラクター × 絵の種類（× 表情）からプロンプトとネガティブを組み立てる
    pnginfo.py     生成の条件を PNG に書き込む・読み出す
    forge.py       Colab 側: パイプラインの読み込み、generate / inpaint、Drive への保存、候補の一覧表示
    export.py      採用した画像を受け渡しの形に書き出す（GPU 不要、サーバーで Claude が実行）
  styles/<name>.yaml           画風（プロンプトとネガティブ）
  templates/face.yaml          絵の種類ごとの型（構図のタグ・大きさ・書き出しの大きさ）
  templates/fullbody.yaml
  characters/<id>/character.yaml   キャラクターの設定
  characters/<id>/source/          採用した元の画像（依頼者から受け取ったもの）
  characters/<id>/face.png など     書き出した受け渡しの形
  notebooks/run.ipynb          Colab の入口
  tests/
  requirements-colab.txt       Colab で入れるライブラリ（版を固定）
  README.md / CLAUDE.md / HANDOVER.md
```

### 5.1 設定ファイル

**styles/<name>.yaml**: 画風。`prompt`・`negative`。最初に色付きのアニメ調を 1 つ作る。今の白黒の漫画のプロンプトはノートブックの記録としてだけ残し、画風としては作らない。

**templates/<name>.yaml**: `width`・`height`・構図のタグ（`prompt`・`negative`）・書き出しの大きさ（顔は 256、全身は縮めない）。

**characters/<id>/character.yaml**: 次の項目を持つ。
- `name`、性別・人数のタグ（`1boy` など）、役割（メモ）
- 外見のタグ: 髪・目・体格・服・持ち物
- `style`: 使う画風の名前
- `expressions`: 表情の名前 → 追加するタグ（通常の顔で使う表情のタグも含む）。**表情の一覧はキャラクターごとに持つ**（Claude の判断）。全員に共通の一覧は作らず、「知らない表情名」はそのキャラクターの `expressions` のキーと比べる。ボルグの最初の一覧は、設定の下書きに入れて依頼者が確認する
- `inpaint`: 採用した顔に対する描き直す範囲（四角）。顔を採用した後に Claude が書く

ゲームの ID（`ally05`）をキャラクターの ID に使ってよいが、リポジトリはそれがゲームの何かを知らない（ただの名前）。

### 5.2 プロンプトの組み立て

- キャラクターの人数・性別 → キャラクターの外見 → 型の構図 → 表情 → 画風 → 品質のタグ、の順に並べる。細かい並びは Animagine XL 4.0 の推奨に合わせて実装者が決める
- ネガティブは 画風 + 型 + キャラクター（あれば）を合わせる
- 同じタグが重なったら 1 つにする。重み付きのタグ（`(thin eyebrows:1.15)`）は重みを無視してタグの名前で比べる（Claude の判断）
- **重み付きのタグは、今のノートブックと同じ A1111 形式の書き方のまま YAML に書ける**ようにする（Claude の判断。依頼者が没セルで使っていたため）。長いプロンプトの扱い方を選ぶときは、この書き方を読めることを条件にする。読めない方法を選ぶなら、書き方の変換を作る
- 長いプロンプト（77 トークンを超える）を扱う。今のノートブックは `lpw_stable_diffusion_xl` のカスタムパイプラインを使っている。**これが inpaint でも使えるかは確かめていない。** 使えない場合は、長いプロンプトを扱う別の方法（compel など）に替える。計画の段階で調べる

### 5.3 生成の条件の記録

PNG の `parameters` に JSON で書き込む（今のノートブックと同じキー名を引き継ぐ）:
- 今と同じ: `prompt`・`negative_prompt`・`seed`・`guidance_scale`・`num_inference_steps`・`sampler`・`model`・`width`・`height`・`run_id`
- 追加: `character`・`template`・`style`・`expression`・`overrides`（5.7）、リポジトリのコミット、diffusers・transformers・torch の版、GPU の名前。inpaint のときは入力画像のファイル名と描き直した範囲・強さ

書き出しのとき、`characters/<id>/source/` の各 PNG からこれを読み出し、`params.json` にまとめる。

### 5.4 書き出し（受け渡しの形）

```
characters/<id>/
  face.png            256×256
  face_<表情>.png      256×256
  fullbody.png        元の大きさ
  params.json         ファイル名 → 生成の条件
```

- 縮小は Pillow の高品質な縮小（Lanczos）で 1 回だけ行う
- 顔の元画像が正方形でなければ止めて理由を出す
- ゲーム側のファイル名（`ally05-face.png` など）への付け替えは character-tactics 側で行う

### 5.5 ノートブック（Colab の入口）

1. 準備のセル: clone（2 回目以降は pull）→ `requirements-colab.txt` を入れる → Drive をつなぐ → モデルを読み込む
2. 顔のセル: `forge.generate("ally05", "face", n=8)`。生成後、候補を縮小した一覧をノートブックに表示し、ファイル名とシードを出す
3. 表情のセル: `forge.inpaint("ally05", "angry", source=..., n=4)`
4. 全身のセル: `forge.generate("ally05", "fullbody", n=4)`

シードはランダムが既定で、`seeds=[...]` を渡せば固定の一覧で生成する（今のセルの 3 通りを 1 つの関数で扱う）。保存先は Drive の `illust-asset-forge/runs/<run_id>/`、ファイル名は `<id>_<型>[_<表情>]_<seed>.png`。

### 5.7 Colab で試しながらプロンプトを直す（依頼者が決めた: 引数で上書き）

- `generate` と `inpaint` は、足すタグ・消すタグを引数で受け取る（例: `forge.generate("ally05", "face", extra="scar on cheek", remove="smile")`）。ネガティブにも同じように足す・消すを渡せる。guidance・steps も引数で上書きできる
- 依頼者は Colab の中だけで試し、リポジトリの YAML は書き換えない（直した YAML は GitHub に戻らず、次の pull でぶつかるため）
- 上書きした内容は、組み立てた結果のプロンプトとは別に、PNG の条件に `overrides` として記録する
- 採用した絵を受け取った Claude が、`overrides` を見て `character.yaml` などの設定に戻し、コミットする。以後は上書きなしで同じプロンプトになる

### 5.6 ライブラリの版

- `requirements-colab.txt` で diffusers・transformers・accelerate・safetensors の版を固定する。今のノートブックの出力に diffusers の廃止予定の警告が出ているため
- torch は Colab に入っているものを使い、固定しない（入れ直しが重いため）。代わりに版を PNG に記録する
- このサーバーでのテスト用には、GPU を使わない部分の依存（PyYAML・Pillow・pytest）だけを入れる。diffusers・torch は forge.py の中でだけ import し、テストでは読み込まない

## 6. テスト

- GPU なしで動く部分を pytest で確かめる: 設定の読み込みと検証のエラー、プロンプトの組み立て（順番・重複の除去・表情のタグ）、PNG の条件の書き込みと読み出し、書き出し（大きさ・正方形の検査・`params.json`）
- forge.py（GPU を使う部分）は Claude が動かせない。依頼者が Colab で、準備・顔・表情・全身の各セルを 1 回ずつ実行して確かめる。その手順を README に書く

## 7. 最初に試すこと（ボルグ）

1. Claude が `characters/ally05/character.yaml` の下書きを `assets/units/ally05.json`（盾・近接・スキル「引きつける」・色 `#7a8a9a`）から書き、依頼者が確認する
2. 依頼者が Colab で顔を生成して 1 枚選び、添付する
3. Claude が書き出す。添付で条件が残ったかを確かめる
4. 表情の差分・全身絵も同じ流れで作る
5. character-tactics 側で顔を差し替えて見え方を試すのは、別の作業（このリポジトリでは行わない）

## 8. 気をつけること

- 今のノートブックで作った絵（「奇跡の一枚」など）を、新しい作りで同じシードから再現することは求めない（Claude の判断。白黒の女性の絵で、今回の用途と違うため）
- 同じシードでも、GPU の種類やライブラリの版が変わると同じ絵にならないことがある。版を固定し、条件を記録しても、完全な再現は保証できない。採用した元の画像を `source/` に残すのはそのため
- 今のゲームの表示の大きさ（64px・32px）では、細い線がつぶれて見える見込みが高い。見え方の判断は character-tactics 側で試してから依頼者が行う
- 1〜2 体だけなら今のノートブックで足りる。リポジトリが割に合うのはキャラクターが増えて作り直しが続くとき。最初の範囲を小さく保つ

## 9. 実装者に任せること

- 各ライブラリの固定する版、長いプロンプトの扱い方（5.2 の調査の結果による）
- タグの細かい並び、構図のタグ・色付きの画風のプロンプトの最初の中身（依頼者が Colab で試しながら直す前提）
- inpaint の強さ・ぼかしの幅の既定値
- 候補の一覧表示の見た目
- 設定ファイルの細かいキー名
