# 切り出しと背景消し（cutout）の設計

2026-11-24。最初のコピー先で顔グラのために足した「顔の切り出し」と「背景除去」を、絵の種類を問わない仕組みとして forge 本体に入れる。

## 意図

生成した絵は、注目するもの（顔グラなら顔、全身絵なら全身、将来は武器なら武器だけ・食べ物なら食べ物だけ）の周りに背景が残る。受け渡しには、注目するものだけを残して背景を透明にし、用途に合う範囲で切り抜いた絵が要る。

- 注目するものは**絵の種類（テンプレート）で決まる**
- どこを切り出すかは**絵の用途で変わる**ので、依頼者がその都度指示する
- コピー先では、顔だけに作った（`face_crop`・`crop_review`・`matte`）。色で背景を消す方法では背景の飾りや髪に囲まれた白が消えず、背景除去モデルのマスクで消すようにした経緯がある

以前の記録（コピー先の UPSTREAM.md、forge の HANDOVER.md）に「顔の構図・切り出しは forge に戻さない」とあるが、依頼者はこの判断を取り消した（2026-11-24）。

## 目標

1. 書き出し（`python -m artgen.export <id>`）が、テンプレートごとの設定に従って、元の絵から 1 つ以上の出力を切り抜き、背景を透明にして書く
2. 背景の消し方は、マスク（背景除去モデル）と色（外につながる白と指定した色）から選べる。マスクが間違えた所は多角形で手で消せる
3. マスクは Modal の CPU で作る（`python -m artgen.cloud matte <id>`）
4. 切り出しの承認用ページを作れる（何人分でも 1 枚に）
5. 候補のページで、候補の隣に背景を消した絵を並べる（選ぶ前に、背景が消えるか分かるように）
6. 候補のページを、キャラクターごとの見出しの下に並べ、サムネイルを JPEG にする（200 枚でも Artifact の上限 16MB に収める）
7. 回りの記録をまとめる `python -m artgen.cloud merge`
8. テストから本物の Modal を呼べないようにする守り（`tests/conftest.py`）
9. 顔のテンプレートの写し方を `portrait` から `upper body` にする

## 目標でないこと

- 武器・食べ物などのテンプレートや見本を作ること。必要になったときに作り、物で背景が消えるかをその場で試し、要るなら forge を直す
- 物用の背景除去モデル（BiRefNet など）を入れること。今回はキャラクターで効果を確かめた anime-seg だけ
- 顔や物の位置を自動で見つけて切り出す範囲を決めること（範囲は依頼者の指示）
- コピー先（各作品のリポジトリ）を書き換えること。コピー先の UPSTREAM.md を「戻した」に直すのは、コピー先の側の別の作業
- 見本 4 人の絵を新しい顔のテンプレートで作り直すこと

## やってはいけないこと

- 背景除去のモデルを Claude のサーバーで動かす（メモリ 1.9GB で推論するとスワップで応答しなくなった。2026-11-24）。onnxruntime を手元の仮想環境・`pyproject.toml` の依存に入れない
- テストから本物の Modal を呼ぶ
- ゲーム側の事情（画面の大きさ・作品の背景色・ゲームの名前）を forge に書く。コピー先にある作品固有の背景色の定数や、画面ごとの表示の大きさと名前を並べた承認用ページの欄は持ち込まない
- コピー先のキャラクター・画像を持ち込む

## 制約

- modal は `modal_app.py` の中でだけ import する（`CLAUDE.md`）。`cloud.py` は使う関数の中で `modal_app` を import する
- 生成の GPU は T4 だけ。マスクは GPU を使わない（CPU 2・メモリ 4GB）
- 設定の誤りは `ConfigError` で `<相対パス>: <キーの位置>: <何がおかしいか>` の形で止める
- 書き出しは、すべての入力（設定・元の絵・マスク）を検査してから書き始める。途中で止まっても何も書かれない（今の `export.py` の決まり）
- `cutouts` を書いていないキャラクターの書き出しは、今と同じ結果にする（顔は 256px の RGB、全身はそのまま写す）
- Modal のアプリ名・Volume は forge の汎用の名前（`illust-asset-forge`・`illust-asset-forge-models`）を使う

## 作り方の候補

- **A. 書き出しの中に切り出しと背景消しを入れる（採用）**：`character.yaml` に、テンプレートごとの出力の一覧を書く。`export` を 1 回実行すれば、切り抜いて背景を消した絵と `params.json` ができる。コピー先で顔だけに作ったものを、テンプレートごとに広げる形になり、コピー先で確かめた「元の絵やマスクが変わったら止める」検査をそのまま使える。代償は、`export.py` と `config.py` を大きく書き換えること
- **B. 書き出しとは別の切り抜きのコマンドを作る**：`export` を変えずに済むが、書き出しの道が 2 つになり、どちらの絵が最新か・`params.json` がどちらの記録かが分かれる。「古ければ止める」検査も作り直しになる

依頼者は A を選んだ。forge の書き出しは「採用した絵から受け渡しの形を作る」唯一の道なので、切り出しもそこに入れる。

## 決まったこと

### 設定（`character.yaml` の `cutouts`）

テンプレートの名前ごとに書く。`face` の設定は、顔（`face.png`）と表情（`face_<表情>.png`）の全部に同じ範囲で効く（表情は顔を描き直しただけで構図が同じため）。

```yaml
cutouts:
  face:
    background: matte          # matte | colors | none
    erase:                     # matte のときだけ。マスクが体の一部と見た背景の飾りを消す多角形（元の絵の画素の座標）。省いてよい
      - [[10, 20], [80, 20], [60, 90]]
    outputs:
      - {suffix: "", box: [212, 120, 812, 720], width: 256}
      - {suffix: "-small", box: [312, 180, 712, 580], width: 128}
  fullbody:
    background: matte
    outputs:
      - {suffix: "", box: null, width: null}
```

- `background`
  - `matte`：`characters/<id>/matte/` のマスクで透明にする。書き出しでは、マスクの値の 128 以下を透明・200 以上を不透明にし、その間だけをなだらかにする（`harden`。迷った値をそのまま透明度にすると背景の白が半透明のもやで残るため）。その後 `erase` の多角形を透明にする
  - `colors`：切り出した範囲の四辺から続く白（全チャンネル 240 以上）と `clear_colors` に当たる色を透明にする（コピー先の今までの方法）。`clear_colors` は `{min, max_rg, max_gb, min_rg?}` の一覧で、`colors` のときだけ書ける
  - `none`：透明にしない（切り抜いて縮めるだけ）
- `outputs`：1 つ以上。`suffix` は出力の名前に付ける文字（`face.png` → `face-small.png`。`""` は元と同じ名前）。同じテンプレートの中で `suffix` は重ならない。`""` は 1 つまで
- `box`：`[x0, y0, x1, y1]`（元の絵の画素）。`null` は絵の全体。元の絵の外にはみ出したら `ConfigError`
- `width`：書き出す幅。高さは範囲の縦横の比で決まる（四捨五入）。`null` は縮めない
- `cutouts` に書いていないテンプレートの絵は、今の書き出しのまま（`export_size` で縮める、または写す）
- 別の入力の出力が同じ名前になる（表情名 `normal` と `normal-small` など）ときは、書く前に止める（コピー先の検査）
- 知らないキー・型の誤りは `ConfigError`

出力は透明な PNG（RGBA）。縮めるときは、アルファを掛けた形で縮めて透明の縁が黒ずむのを防ぐ（コピー先の `render_face` と同じ）。

### 範囲の決め方

依頼者が用途と切り出す所を指示し、Claude が元の絵を見て座標に直して `character.yaml` に書く。承認用ページで依頼者が見て決める（Claude の判断で決まった値にしない）。この流れを `CLAUDE.md` に書く。`CLAUDE.md` の「Claude が顔を見て範囲を決めることもしない」は表情の範囲（`inpaint_box`）の決まりで、切り出しの範囲には当てはまらないことも書き分ける（コピー先の `CLAUDE.md` と同じ）。

### マスク（`artgen/matte.py`・`cloud matte`）

- モデルは anime-seg（`skytnt/anime-seg` の `isnetis.onnx`）。SHA-256（`f15622d8…6e99`）を固定し、Modal で取ったファイルが違えばマスクを作らない
- `modal_app.py` に `matte_remote`（CPU 2・メモリ 4GB・timeout 1800 秒、版を固定した onnxruntime・numpy・Pillow・huggingface_hub・PyYAML の image）と `run_matte` を足す。モデルは生成と同じ Volume にキャッシュする
- `python -m artgen.cloud matte <id> [<id> ...]`：`cutouts` で `background: matte` のテンプレートの元の絵（`source/` のうち該当する名前）を全部送り、`characters/<id>/matte/<元の絵の名前>` に置く。`matte.json` に、モデルと元の絵の SHA-256 を記録する。応答を待つあいだに元の絵が差し替わったら止める。マスクはリポジトリに入れる（書き出しを Modal 無しで再現するため）
- 書き出しは、マスクが無い・元の絵より古いときに止まり、`cloud matte` を案内する
- `modal_app.py` の生成用の image の `add_local_dir` の ignore に `characters/*/matte` を足す

### 書き出しの記録（`params.json` の `cutouts`）

テンプレートごとに、使った設定（`background`・`erase`・`clear_colors`・`outputs`）、元の絵の SHA-256、マスクの SHA-256（`matte` のとき。書き出しが描画に使った bytes から求める）を記録する。承認用ページは、この記録が今の設定・元の絵・マスクと合わないときにページを作らない（範囲を直したのに書き出していないページで承認すると、承認が意味を失うため）。

### 確認図

出力ごとに、切り抜いた範囲で、透明にした画素（アルファが半分未満）を赤で塗った絵を `local/check/<id>/<出力の名前>` に書く（リポジトリに入れない）。

### 承認用ページ（`python -m artgen.cutout_review <id> [<id> ...] [--out PATH]`）

コピー先の `crop_review` を汎用にする。1 人なら `local/check/<id>/review.html`、何人分かなら 1 枚（既定 `local/check/reviews/<日時>.html`。全員を先に検査し、1 人でも古ければ作らない。元の絵・確認図は JPEG に縮める）。テンプレートごとに次を並べる。

- 元の絵に出力ごとの範囲を色違いの枠で描いた絵と、枠なしの絵
- 出力ごとの確認図
- 出力ごとの書き出した絵を、書き出した大きさで、市松模様と表示用の背景色（下）の上に

既定で並べるのは元の絵（`face.png`・`fullbody.png`）の分だけ。表情（`face_<表情>.png`。元の絵の一部を描き直した差分）は、`--variants` を付けたときだけ、差分ごとに確認図と書き出した絵を並べる（依頼者の判断。2026-11-24）。差分を並べないときも、検査（記録が今の設定・元の絵・マスクと合うか）は差分を含めた全部で行う。

### 表示用の背景色（`defaults.yaml` の `preview_background`）

任意。`#rrggbb`。候補のページの背景を消した絵と、承認用ページの書き出した絵を置く色。書かなければ市松模様。forge の `defaults.yaml` には書かない（コピー先が作品の色を書く）。

### 候補のページ（`review_page.py`）と `cloud generate`・`page`・`merge`

- 候補をキャラクターごとの見出し（`名前（ID）`。設定が読めなければ ID）の下に、番号順に全部並べる。サムネイルは JPEG（quality 80）
- `generate`・`merge`・`page` は、既定でページを作る前に、マスクがまだ無い候補を 40 枚ずつ Modal に送り、候補の隣に `<名前>.matte.png` を置く（`ensure_candidate_mattes`。区切りごとに保存するので、落ちても済んだ分は残る）。ページでは候補と、背景を消して表示用の背景色（無ければ市松模様）に置いた絵を 2 枚並べる。`--no-matte` で止める。候補はテンプレートを問わず全部送る
- 背景消しが落ちても、絵と回りの記録は残す。`page` でやり直せると案内して止まる
- `merge ROUND_JSON ROUND_JSON [...]`：2 つ以上の回りの候補を、元の番号順に通し番号を振り直して 1 つの記録（`merged_<日時>.json`）とページにする。元の記録は変えない（Modal の 1 回は 1 時間で打ち切られて絵が全部失われるので、人数が多いときは分けて動かすため）

### テストの守り（`tests/conftest.py`）

`artgen.modal_app` を、呼ぶと落ちる偽物に autouse の fixture で置き換える。Modal を使う道のテストは、自分の偽物で置き換える。

### 顔のテンプレート

`templates/face.yaml` の `prompt` の `portrait` を `upper body` にし、`negative` から `upper body` を外す（`portrait` は顔を寄せるので頭が上の辺で切れ、切り出す余地が無いため）。`inpaint.box` は変えない。この既定値は顔のアップのときの値で、上半身の絵とは合わないので、表情を作るときはキャラクターごとに範囲を決める（README に書く。コピー先の README と同じ）。見本 4 人の絵は古いテンプレートで作ったまま（README に書く）。

### 文書

`README.md`（ファイルの地図・書き出し・節 10 の Modal の道）と `CLAUDE.md`（範囲の決め方、マスクをこのサーバーで作らない、`matte/` をリポジトリに入れる）を直す。`HANDOVER.md` の「切り出しは持ち帰っていない」の記述を今の状態に直す。

### 本物の Modal での確かめ（Claude の判断）

見本 4 人の `character.yaml` には `cutouts` を入れない（見本の書き出しの結果を変えない。`cutouts` の書き方の実例は README に書く）。計画の最後に、forge を一時フォルダへ clone し、その中だけで見本 1 人に仮の `cutouts` を書いて、`cloud matte`・`page`（候補の背景消し）・`export`・`cutout_review` を本物の Modal で 1 回通す。結果はコミットしない。Modal を動かす前に、依頼者に枚数と利用額の見込みを伝える（`CLAUDE.md`）。
